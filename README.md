# ReqMan sandbox — Smart Home Climate System (fictional)

Test data for ReqMan: **10,005 fictional requirements** in `requirements/`, plus 2 deliberately unreadable files.
Nothing here is real product data. It was generated by `tools/generate-scenario-repo.mts` in the ReqMan repository,
so it can be recreated at any time.

## How to use

1. Clone this repository: `git clone https://github.com/mostafadiab97/Claude_SandBox.git`
2. In ReqMan: **Open repository…** → choose the cloned folder. The first opening indexes all files (a few seconds);
   later openings are almost instant.
3. Experiment freely — create, edit, move, delete. To start over: `git checkout -- . && git clean -fd`
   (or `git reset --hard origin/main`).

**Structure.** A title page with glossary and revision history, then one chapter per product area — Heating
Control, Mobile App, Cloud Service, Device Display & Controls, Power & Hardware, Connectivity, Safety & Security.
Each chapter: *Stakeholder needs* (with use cases) → *System requirements* → software / hardware / interface
requirements beneath each system requirement (some chains go several levels deeper, some have design elements)
→ *Verification* (test cases) → *Risks* → *Defects and change requests*.

**Fields.** All statuses (Draft, Review, Approved, Obsolete), priorities including empty ones, 12 owners
(including Arabic, German, French and Japanese names) and 14 tags.

**Links.** Every link records the state of the item it points to when the link was confirmed. 175 links are
*suspect* — their target was (as if) edited afterwards — so ReqMan marks them ⚠ until someone confirms them.

**Texts.** One-line "shall" statements, rationale, acceptance-criteria lists, Markdown tables, numbered test
steps, code blocks, Arabic right-to-left text.

## Deliberately broken data (chapter 9)

ReqMan should report these, never crash on them:

| Problem | How ReqMan shows it |
| --- | --- |
| A link to `SYS-ZZZZZZ`, which does not exist | Status-bar problem list |
| A parent `SYS-YYYYYY` that does not exist (the item appears nowhere in the tree; find it with search "PROBLEM") | Status-bar problem list |
| `items/SYS-BROKEN.md` — no YAML header | Status-bar problem list ("could not be read") |
| `items/SW-BADYML.md` — broken YAML | Status-bar problem list |
| Status "Done", not in the schema | Message when the item is opened; saving is refused until fixed |
| Unknown link type "blocks" | Message when the item is opened |
| A test case with an `SW-` ID | Warning when the item is opened |
| A risk file renamed by hand to `RSK-RENAMD.md` | Opens normally (repository-wide check comes later) |
| A file with header keys ReqMan doesn't know (`x-imported-from: DOORS`) | Not a problem: the keys must still be there after you edit and save the item |
